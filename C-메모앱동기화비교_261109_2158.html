결론

강점 (대중 앱과 동급 이상)

  • 조용한 덮어쓰기 차단 (버전 sha 검사)
  • 충돌 시 두 내용 모두 이력 보존
  • 전체 변경 이력 복원
  • 종단간 암호화

약점

  • 병합 단위 = 데이터 전체 1개
  • 서로 다른 업무 수정도 충돌 처리
  • 실시간 반영 없음 (창 복귀 시 확인)

권장

  • 2단계 도입: 항목 단위 3방향 병합
  • 같은 항목 같은 필드만 선택 창
  • CRDT(4단계)는 과잉

동기화 방식 4단계 (병합 단위가 작을수록 충돌 감소)

구현 난이도 1 → 4 증가 서버 요건 1~3: 파일 저장소로 가능 4단계 전용 동기화 서버 필요

현재 앱 상세 (코드 역추적)

권장 개선안: 2단계 (항목 단위 3방향 병합)

기준본 보관

  • 마지막으로 받은 서버본 = base
  • 메모리 보관 (추가 저장 없음)

충돌 시 3방향 비교

  • base vs 내 화면 vs 서버
  • tasks, whiteboard: id 기준
  • monthlyLogs, 휴무, 연차: 키 기준

자동 합침

  • 한쪽만 바뀐 항목 → 그쪽 채택
  • 추가/삭제도 항목별 반영

진짜 충돌만 질문

  • 같은 항목 같은 필드 양쪽 수정
  • 해당 항목만 선택 창 표시
  • 기존 이력 보존 유지
충돌 창 빈도 대폭 감소 서버 변경 없음 (GitHub 그대로) API 호출 변화 없음 수정 범위 index.html 저장 엔진 앱 반영 재빌드 자동
